    Train the Q-Learning Agent

    Offline training inside the simulation (Section 3.5). The trained Q-table is saved to models/q_table.json.

    Learning curve

    RL formulation (Section 5.2.1)

    • State: task type, candidate node, node queue-delay bucket, predicted deadline feasibility.
    • Action: assign the task to one eligible node (deferral when none is feasible).
    • Reward: +1 deadline met / −2 missed, − 0.5 × completion ratio, − energy weight × normalised energy, − 0.5 if node overloaded; scaled by priority.
    • Policy: tabular Q-learning, ε-greedy exploration (0.3 → 0.02), α = 0.15, γ = 0.3.
    • Why learning helps: nodes have run-time variability that the planner cannot see; the agent learns which nodes really deliver on time.

    Policies compared

    • Fixed mapping – each application always goes to its home node (traffic→N1, surveillance→N2, emergency→N3, environment→N4).
    • Round robin – nodes are used in turn.
    • Least loaded – node with the lowest CPU utilisation.
    • Threshold reactive – home node unless it crosses 80% CPU / 150 ms queue, then least loaded.
    • AI (Q-learning) – filters infeasible and overloaded nodes, prefers nodes predicted to meet the deadline, then chooses using the learned Q-values (latency, queue, transfer, energy and reliability).
